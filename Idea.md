# Loyalty Program — Концепция продукта

## Суть

Независимая платформа программы лояльности для ритейла.
1С — источник событий о покупках. Система лояльности — отдельное ядро с гибким конфигуратором механик.
Клиент взаимодействует только через мобильное приложение.

---

## Компоненты системы

### 1. Backend API — ядро лояльности

- Движок начисления и списания баллов по настроенным правилам
- REST API для интеграции с 1С и мобильным приложением
- Поддержка двух режимов работы сети: единая сеть / изолированные магазины

### 2. Конфигуратор — Web Admin Panel

Позволяет настраивать механику лояльности без изменения кода.

**Два уровня доступа:**
- **Ритейлер** — базовые настройки: процент начисления, минимальная сумма покупки для бонуса, срок действия баллов
- **Администратор платформы** — сложные правила: мультипликаторы, временные акции, категорийные бонусы, конфигурация тиров

**Поддерживаемые механики:**

| Механика | Описание |
|---|---|
| Баллы | % от суммы покупки начисляется на счёт |
| Кэшбэк | % возврат деньгами или бонусами |
| Штампы (Punch card) | Купи N раз → получи бонус или товар бесплатно |
| Уровни (Тиры) | Bronze / Silver / Gold с разными % начисления |
| Акции | Двойные баллы в период, бонус за категорию товара |
| Реферальная программа | Бонус пригласившему и приглашённому за первую покупку друга |
| Геймификация | Колесо фортуны, бейджи, челленджи за выполнение условий |

**Настройки списания:**
- Минимальный баланс для списания
- Максимальный % от суммы чека, который можно оплатить баллами
- Курс обмена баллов (1 балл = X рублей)

### 3. Мобильное приложение — для клиента

**Функциональность:**
- Регистрация и авторизация по номеру телефона (OTP)
- Текущий баланс баллов
- Текущий уровень лояльности и прогресс до следующего
- QR-код для предъявления на кассе (динамический, с TTL)
- Привязка физической карты (штрихкод / номер карты)
- История транзакций: начисления и списания с датой и суммой
- Активные акции и предложения
- Push-уведомления: начисление баллов, сгорание баллов, персональные акции
- Карта лояльности в Apple Wallet / Google Wallet — альтернатива установке приложения
- Офлайн-генерация QR-кода (TOTP-подобный алгоритм) при отсутствии интернета на телефоне
- Чат поддержки / FAQ внутри приложения

### 4. Интеграция с 1С

1С является источником данных — отправляет события о покупках в API системы лояльности.

**Webhook при завершении продажи:**
```
POST /api/v1/transactions
{
  "store_id": "...",
  "client_id": "...",        // телефон, карта или ID из QR
  "amount": 1500.00,
  "items": [...],            // состав чека (для категорийных правил)
  "timestamp": "..."
}
```

**Ответ:**
```json
{
  "points_earned": 75,
  "balance": 420,
  "tier": "Silver"
}
```

**Дополнительные методы API:**
- `GET /api/v1/clients/{id}/balance` — проверка баланса перед оплатой баллами
- `POST /api/v1/transactions/redeem` — подтверждение списания баллов
- `POST /api/v1/transactions/refund` — возврат товара: корректировка начисленных/списанных баллов по исходной транзакции

**Офлайн-устойчивость:**
Если 1С временно не может достучаться до API (нет интернета), события помещаются в локальную очередь и отправляются после восстановления соединения. Баллы начисляются с задержкой, но не теряются.

**Идемпотентность:**
Каждая транзакция передаётся с уникальным `transaction_id`. Повторная доставка одного и того же события (например, после повтора при таймауте) не приводит к повторному начислению/списанию.

**Безопасность webhook:**
Запросы от 1С подписываются (HMAC с секретным ключом на магазин) или передаются с API-ключом по mTLS. Запросы без валидной подписи отклоняются.

**SLA и деградация:**
Целевое время ответа на webhook — менее 300 мс, так как касса ждёт ответ во время оплаты клиента. Если API лояльности недоступно, продажа всё равно завершается без начисления баллов; событие переотправляется позже по той же логике, что и офлайн-очередь 1С.

**Тестовый контур (sandbox):**
Отдельное тестовое окружение и тестовые `store_id` для интеграторов — позволяет проверить webhook до подключения боевого магазина.

## Режимы работы сети

| Режим | Описание |
|---|---|
| Единая сеть | Баллы общие для всех точек, один аккаунт клиента |
| Изолированные магазины | Каждый магазин — своя независимая программа |
| Смешанный | Настраивается в конфигураторе под нужды бизнеса |
| Коалиция | Общий пул баллов между несколькими независимыми брендами/ритейлерами |

---

## Идентификация клиента на кассе

1. **QR-код** из мобильного приложения — динамический, с ограниченным временем жизни (TTL)
2. **Физическая карта** — штрихкод или номер карты
3. **Номер телефона** — ввод вручную кассиром

**Регистрация на кассе:**
Кассир вводит номер телефона нового клиента → система создаёт аккаунт → клиент получает SMS со ссылкой на приложение. Снижает порог входа для новых участников программы.

## Аналитика для ритейлера

Дашборд в конфигураторе — ключевой инструмент для оценки эффективности программы.

**Метрики клиентской базы:**
- Количество активных участников (покупка за последние 30/90 дней)
- Прирост новых участников по периодам
- Распределение по тирам (Bronze / Silver / Gold)

**Метрики покупок:**
- Средний чек участников программы vs неучастников
- Частота покупок по сегментам
- Клиенты под риском оттока (нет покупок > N дней)

**Метрики баллов:**
- Начислено vs списано (коэффициент использования)
- Баллы под угрозой сгорания (стимул к рассылке)
- Эффективность акций: прирост чека в период акции

**Сегментация клиентов (RFM):**
- Автоматические группы: "лояльные", "под риском", "спящие", "новые"
- Экспорт сегмента для маркетинговой кампании

---

## Маркетинговые кампании

Инструменты для работы с клиентской базой через конфигуратор.

**Типы коммуникаций:**
- Push-уведомление в приложение
- SMS на номер телефона

**Триггерные (автоматические):**
- Начисление баллов → push "Вам начислено X баллов"
- За N дней до сгорания → push/SMS "Ваши баллы сгорят через 7 дней"
- Первая покупка → приветственное сообщение с бонусом
- Нет покупок 30/60/90 дней → реактивационная кампания

**Ручные (по сегменту):**
- Ритейлер выбирает сегмент из аналитики → составляет текст → отправляет

## Антифрод

Защита от злоупотреблений со стороны клиентов и кассиров.

- Лимит на списание баллов в сутки на одного клиента
- Минимальный интервал между операциями (защита от повторного сканирования QR)
- Флаг подозрительных операций: списание в нескольких магазинах за короткое время
- Лог всех операций с привязкой к кассиру и устройству

---

## Безопасность и защита данных (Compliance)

- Обработка персональных данных в соответствии с 152-ФЗ: согласие пользователя на обработку при регистрации
- Публичная оферта программы лояльности и политика конфиденциальности
- Шифрование данных при хранении и передаче (TLS, шифрование чувствительных полей в БД)
- Журналирование доступа к персональным данным клиентов

---

## Модель развёртывания платформы

Открытый вопрос архитектуры: единая мультитенантная платформа для множества ритейлеров (с биллингом и тарифами самой платформы, изоляцией данных между арендаторами) vs выделенное развёртывание под каждого крупного клиента. От этого решения зависит модель данных (`tenant_id`), self-service онбординг новых ритейлеров и тарификация платформы.

## Ключевые принципы

- **Независимость от 1С**: система лояльности работает как отдельный сервис, 1С — только источник событий
- **Гибкость механик**: все правила настраиваются через конфигуратор, без деплоя
- **Масштабируемость**: поддержка как одного магазина, так и крупной сети
- **Безопасность**: динамические QR-коды с TTL исключают мошенничество с повторным использованием
- **Ценность для ритейлера**: аналитика и маркетинговые инструменты как основной аргумент внедрения
- **Устойчивость**: офлайн-очередь в 1С гарантирует, что ни одна транзакция не потеряется
