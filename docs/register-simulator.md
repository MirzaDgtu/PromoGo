# Эмулятор кассы (possim)

`cmd/possim` — утилита, которая ведёт себя как модуль лояльности в 1С на
кассе: шлёт продажи, списания и возвраты в store-key API PromoGo и держит
офлайн-очередь. Нужна, чтобы проверять API и наполнять Admin Web данными до
появления настоящей базы 1С, и как образец поведения для того, кто будет
писать модуль 1С.

Эмулятор фискальной части (ККТ) здесь не нужен: касса печатает чек и общается
с ОФД, а с PromoGo говорит только 1С.

## Запуск

```powershell
$env:PROMOGO_STORE_KEY = '<API-ключ магазина из Admin Web → API-ключи>'
# по умолчанию http://127.0.0.1:8090 — порт app из deployments/docker-compose.yml
go run ./cmd/possim sale -phone +79261234567 -amount 1250
```

| Команда | Что делает |
|---|---|
| `sale -phone -amount [-id] [-offline]` | продажа, начисление баллов |
| `redeem -phone -points -amount [-id]` | оплата баллами: поиск клиента по телефону, затем списание |
| `refund -original -amount [-type] [-id] [-offline]` | возврат (полный или частичный) по продаже или списанию |
| `balance -phone` | баланс клиента в этом магазине |
| `qr -payload` | опознать клиента по QR из мобильного приложения |
| `flood [-n 20] [-clients 8] [-redeem-share 0.3] [-seed]` | поток покупок от покупателей `+79990000001…` |
| `replay` | дослать офлайн-очередь |
| `queue` | показать офлайн-очередь |

## Правила, которые эмулятор показывает (и которым должен следовать модуль 1С)

- **transaction_id выбирает касса** — номер документа 1С. Повтор запроса с тем
  же id и теми же данными API отвечает исходным результатом с
  `replayed: true` и баллы второй раз не начисляет. Тот же id с другими
  данными — `409`.
- **Повторы.** Сетевая ошибка, `429` (с учётом `Retry-After`) и `5xx` —
  временные: запрос повторяется с тем же id. Остальные `4xx` — окончательный
  отказ, повторять бессмысленно.
- **Офлайн-очередь.** Продажа или возврат, которые не удалось доставить,
  записываются в локальный файл (`possim-queue.jsonl`) и досылаются по
  порядку при восстановлении связи — перед следующей операцией или командой
  `replay`. Досылка останавливается на первой временной ошибке, чтобы поздние
  продажи не обогнали ранние; окончательно отклонённые записи выводятся и
  удаляются.
- **Оплата баллами офлайн невозможна**: без связи баланс не проверить, поэтому
  списание в очередь не ставится, касса принимает оплату деньгами.
- Списание и продажа одного чека могут идти под одним transaction_id:
  идемпотентность считается отдельно по типу операции.

## Сценарии проверки

```powershell
# идемпотентность: второй запрос вернёт replayed
go run ./cmd/possim sale -phone +79990000001 -amount 1000 -id CHECK-1
go run ./cmd/possim sale -phone +79990000001 -amount 1000 -id CHECK-1

# офлайн: две продажи в очередь, затем досылка
go run ./cmd/possim sale -phone +79990000002 -amount 500 -offline
go run ./cmd/possim sale -phone +79990000002 -amount 700 -offline
go run ./cmd/possim queue
go run ./cmd/possim replay

# наполнить «Обзор», «Клиентов» и «Аудит»
go run ./cmd/possim flood -n 40 -clients 10
```

## SMS-приглашение нового клиента

Первая продажа на новый телефон регистрирует клиента. Если на магазине
включено «SMS-приглашение в приложение» (Admin Web → Организации и магазины
→ Изменить) и задан `PROMOGO_INVITE_APP_URL`, клиенту уходит SMS со ссылкой.
Приглашение уходит один раз на номер (DEC-034). В разработке SMS только
пишется в лог приложения:

```powershell
go run ./cmd/possim sale -phone +79991112233 -amount 1000
docker logs promogo-app-1 2>&1 | Select-String app_invite
```
