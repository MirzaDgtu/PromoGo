# Q: Давай обсудим данные дополнения. На мой взгляд это необходимо сделать

## Answer

Expanded from original query via graph vocab: [registration, identity, administrative, security, client, customer, store, api, key, multistore, configuration, configurable]. Рекомендация: реализовать три раздельных auth-контура. Клиент: OTP по телефону, короткий access token, ротируемый refresh token/session, /me, logout/revoke, rate limits и consent record. Сотрудники: отдельная admin identity через OIDC, внутренний RBAC с membership, привязанным к retailer/organization и при необходимости store; MVP-роли platform_admin, retailer_admin, store_manager и support/viewer, а права хранить как permissions. 1С: сохранить store API key, но добавить key id, несколько ключей на период ротации, expires/revoked/last_used, аудит и scopes. До реализации нужно ввести Organization/retailer над Store и не привязывать мобильную identity напрямую к текущему store-scoped Client: customer identity должна быть отделена от loyalty membership/account. Последовательность: ADR и OpenAPI, tenant/customer schema, OTP/session, RBAC/admin, API-key lifecycle/audit, затем security/integration tests.
