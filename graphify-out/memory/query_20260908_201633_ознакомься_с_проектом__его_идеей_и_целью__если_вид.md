# Q: Ознакомься с проектом. Его идеей и целью. Если видишь изъяны, допущения и возможности улучшения, то распиши их. Проведи полный аудит приложения

## Answer

PromoGo — независимое ядро лояльности между 1С/POS, мобильным клиентом и админ-панелью; MVP должен доказать полный цикл начисления, просмотра и списания в одном магазине. Аудит текущей рабочей копии выявил production-blockers: несовместимое хеширование новых store API keys; tenant IDOR и повышение retailer_admin до platform_admin; межмагазинный отзыв ключа; неатомарные OTP и refresh rotation; отсутствие проверки blocked customer; fail-open SMS provider; PII в логах; недолговечный audit trail; уязвимый Go 1.25.12. Сильные стороны: слоистая архитектура, decimal money, транзакционный ledger, idempotency и partial-refund locking, route/OpenAPI parity, Redis Lua rate limiter. Нужны P0 security fixes, integration/concurrency tests, outbox notifications, решение tenant/customer identity model и завершение отсутствующих Flutter/React/1C частей MVP.
