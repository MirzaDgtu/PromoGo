# Вопросы по проекту PromoGo

Это единый список продуктовых, интеграционных и технических вопросов для
владельца проекта, клиента, Codex и Claude Code. Он расширяет
[ClientChecklist.md](../ClientChecklist.md) и связывает вопросы с текущей
реализацией. Ответ считается принятым только после записи в [[Decisions]].

Обозначения: **P0** — блокирует пилот или безопасность; **P1** — нужно определить
до production; **P2** — можно решить после валидации MVP.

- [ ] **Q-P0-056:** Делается общее приложение PromoGo или white-label приложение

- [x] **Q-P0-059:** Как мобильное приложение авторизуется в API, обновляет и
  отзывает токены, и как отделены API клиента и API магазина? — см.
  [[Decisions#DEC-004]] и [[Decisions#DEC-006]]: OTP → короткоживущий
  access-токен (HS256, `customer_account_id` как subject) + непрозрачный

  `/auth/logout` и `/auth/logout-all`. Отдельная от store API key
  аутентификация, отдельный middleware (`RequireCustomerSession` vs
  `RequireStoreAPIKey`).
- [ ] **Q-P0-060:** Где хранится FCM token, как обрабатываются несколько устройств
  и отозванные/невалидные токены?

- [x] **Q-P0-066:** Какие роли нужны в MVP: владелец сети, администратор магазина,

  `internal/domain.Role` с explicit permission-картой.
- [ ] **Q-P0-067:** Кто создаёт магазин, выдаёт/ротирует API-ключ и настраивает

## 11. Несоответствия текущей реализации и скоупа

- [x] **Q-P0-101:** Текущая модель хранит клиента и баланс в одном `store_id`.
  При единой сети клиент должен быть сетевым/tenant-level или баланс останется
  магазинным с отдельной агрегацией? — см. [[Decisions#DEC-004]]: добавлен
  `Organization` как родитель `Store`; баланс/ledger остаются
